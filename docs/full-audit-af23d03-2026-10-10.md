# Language Lens audit of af23d03 — 10 October 2026

Audited revision: `af23d036291cbac00d264175d917affd1028339f` (`Broad improvements`). The checkout was clean when this audit began. This report follows the [earlier audit](full-audit-2026-10-10.md) and [repair record](audit-repairs-2026-10-10.md), which describe a different revision.

Four new defects were confirmed. The most serious is an uninstall guard that accepts a shared folder and then schedules recursive removal of its unrelated contents. Fix F1 before distributing another portable release. F2 and F3 prevent recovery in specific damaged or outdated installations; F4 breaks a less frequently reached speech error path. ### F1 — The portable uninstall guard does not establish ownership of the folder contents

Locations: [uninstall.py](../src/language_lens/uninstall.py), lines 45–60, 88–100, and 239–249.

`validate_install_root()` rejects a drive root, the exact home directory, and a linked/reparse root. It then checks the release marker and four expected entries. It accepts a folder containing other files as long as those release entries are also present. `main()` adds the entire accepted folder to the cleanup list; the helper executes `Remove-Item -LiteralPath $path -Recurse -Force`.

A user who copies or extracts the release's contents directly into Downloads, Desktop, or another shared directory can therefore lose unrelated documents after confirming what the dialog describes as removal of the application folder. The archive's normal enclosing `LanguageLens` directory reduces the likelihood but does not enforce the necessary ownership boundary.

**Reproduction:** create a private `shared-downloads` directory, add `_internal/portable-release.json` containing `{"product":"Language Lens","layout":1}`, add the three expected executable names, and add `unrelated-user-document.txt`. Both `validate_install_root()` and `cleanup_command()` accept the directory. The unrelated document lies inside the planned recursive target. This probe did **not** launch the helper; no real user files were deleted.

**Recommended change:** remove only files recorded as belonging to the release and remove directories only when empty, or require a provably dedicated installation folder and refuse unknown content before scheduling whole-folder deletion. A directory name alone is insufficient. Keep the separate consent for shared Argos data.

**Regression check:** a valid marker and executable layout in a folder with unrelated content must preserve that content or refuse the uninstall. Continue checking normal dedicated-folder removal, reparse points, and failed helper startup.

### F2 — A persistent metadata failure traps Settings in a retry loop

Locations: [setup.py](../src/language_lens/ui/setup.py), lines 633–681 and 897–903; [translation.py](../src/language_lens/services/translation.py), lines 107–117; [task_worker.py](../src/language_lens/services/task_worker.py), lines 32–39; [offline.py](../src/language_lens/services/offline.py), lines 174–184.

Argos enumerates every installed package when `get_installed_languages()` runs. A malformed package's `metadata.json` raises before pair readiness can be determined, including when that package is unrelated to the selected direction. Lens correctly reports unknown status rather than treating an inspection failure as a missing model, but it offers no actionable recovery from a persistent corrupt package.

`_status_failed()` clears translation readiness and changes the primary action to **Retry file check**. That action only repeats inspection. Repair and removal require `_translation_ready`, so both remain disabled. Calling the preparation worker independently also fails at its initial `is_pair_installed()` check. The existing staged replacement code can handle some damaged metadata by package name, but Settings cannot reach that recovery action in this state.

**Reproduction:** in isolated app/config/cache storage, create `argos-translate/packages/damaged-model/metadata.json` containing only `{`. Run the actual `status` and `prepare` workers for Dutch → English. Both exit with code 1. The Qt Settings failure state shows **Retry file check**, with repair and removal disabled. No model download or removal was performed by the probe.

**Recommended change:** preserve the unknown-status behavior for permission and transient inspection errors, while adding explicit diagnosis and a recoverable quarantine/repair path for malformed package metadata. Do not silently erase an unknown or shared package. Replacing a healthy selected route alone will not resolve an unrelated malformed directory.

**Regression check:** cover corrupt selected and unrelated package metadata, missing metadata, and transient permission errors. A user must be able to recover without manually editing the package directory, with original files preserved for recovery.

### F3 — Source launch health checks do not test the adapter's actual dependency requirements

Locations: [environment.ps1](../scripts/environment.ps1), lines 34–43; [launcher.ps1](../scripts/launcher.ps1), lines 5–8; [argos_sentences.py](../src/language_lens/services/argos_sentences.py), lines 35–39; [translation.py](../src/language_lens/services/translation.py), lines 62–85.

The environment health expression imports the Argos top-level package and checks the pinned Piper metadata. It neither checks MiniSBD nor exercises the strict version requirements of Lens's sentence adapter. The launcher invokes setup only when that health check fails.

An existing environment containing an older but importable Argos or MiniSBD package consequently passes the launcher gate, while translation later fails because the adapter requires exactly Argos 1.11.0 and MiniSBD 0.9.5. The service's recommended recovery is restarting the batch launcher, which repeats the same accepted health check and skips dependency installation again. Initial setup installs the right pins; this affects upgrades or altered existing environments.

**Reproduction:** execute the launcher's exact health expression in fresh isolated Python processes, with distribution-version lookup simulated as Argos 1.10.0 or MiniSBD 0.9.4. The expression succeeds in both cases. Calling `ArgosTranslator._modules()` then raises `TranslationUnavailable`, caused by the adapter's explicit version rejection. Installed packages were not modified; this is a compatibility-gate probe, not a claim that these older versions were installed on the audited host.

**Recommended change:** share a lightweight dependency compatibility check with the real adapter, including the presence and exact versions of Argos and MiniSBD. Make launcher health fail when that contract is not satisfied so the existing setup path can repair it. Avoid downloading or loading models during the health check.

**Regression check:** absent MiniSBD and incompatible Argos/MiniSBD versions should trigger setup. A compatible environment should continue directly to startup.

### F4 — Missing speech runtime raises `NameError` instead of reporting recovery

Location: [speech.py](../src/language_lens/services/speech.py), lines 87–90; imports at lines 9–10.

The non-Japanese missing-runtime branch calls `recovery_instruction()`, but the module never imports or defines that name. The exception occurs while building the error message, before `_failed()` runs. The player therefore does not enter its error state or deliver the intended recovery instruction.

**Reproduction:** create `SpeechPlayer` with an audit-owned voice directory, make `runtime_ready()` return false, and request English speech. It raises `NameError: name 'recovery_instruction' is not defined`; the player remains idle. Normal Settings/Review controls already check runtime readiness, so this is a service recovery defect, especially if availability changes after a control was enabled. It does not mean ordinary installed speech playback fails.

**Recommended change:** import the existing runtime recovery helper and test this branch. Preserve the different advice for Japanese pronunciation packs.

**Regression check:** an English request with missing runtime must emit an error state containing recovery guidance and launch no worker; the Japanese missing-pack path must retain its pack instruction.

## Existing quality and release limitations

The following remain relevant but are already acknowledged in the project; they are not counted as four additional newly discovered defects.

- **Word meaning:** word candidates are produced independently of sentence context. The curated samples still miss six selected contextual senses. For example, Dutch `zin` in `Ik heb er geen zin in.` yields sentence/phrase/clause candidates, although the full sentence is correctly translated as `I don't feel like it.` The app now labels isolated-word suggestions, but those labels do not improve the model's contextual usefulness.
- **Sentence boundaries:** the recorded Arabic, Chinese, and Japanese examples still merge sentences that the intended corpus separates. Matching a baseline preserves behavior; it does not establish linguistic correctness.
- **Language/UI quality:** native-speaker assessment of all locales, IPA, and voices remains pending. Rendering and successful synthesis do not establish fluent wording or pronunciation quality. The twelve semantic cases are an initial regression corpus, not broad accuracy measurement.
- **Distribution readiness:** the preview is unsigned, and clean-machine Windows 11 verification remains outstanding. This audit's executable checks run on a development host with isolated data and restricted search paths; they cannot substitute for a machine without development dependencies.
- **Licensing:** [the speech provenance record](../THIRD_PARTY_SPEECH.md) already lists unresolved redistribution review, including runtime notices and voice provenance. This audit did not provide legal clearance or publish binaries.
- **Dependency reproducibility:** the Windows Python 3.10 snapshot is pinned, while Python 3.11/3.12 CI installs from declared ranges. The workflows were inspected, but this audit did not execute the remote matrix or validate those interpreters locally.

The download and worker paths have useful existing protections: bounded worker timeouts, restricted inference networking, privacy-conscious diagnostics, archive checks, transactional model replacement, and hash verification for the pinned OCR/sentence/voice/optional-pack assets. These do not establish cryptographic provenance for dynamically indexed Argos packages. Requiring HTTPS and stronger provenance for that separate download channel would be a useful hardening task; no compromised index or malicious model was observed here.
